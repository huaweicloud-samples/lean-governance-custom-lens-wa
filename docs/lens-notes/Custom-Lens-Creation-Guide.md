# 创建自定义检查单指南

> 本文件说明如何基于本仓的检查单模板，为新的架构域或新的评审视角扩展一份自定义检查单。

本仓检查单为**离线 Markdown 模板**，不依赖任何评审工具即可使用。若团队已有自建评审平台（问卷系统、表格协作、内部工具），可按本文档的模板约定把检查单导入对应平台。

## 1. 检查单的文件约定

| 约定 | 说明 |
|---|---|
| 存放位置 | `src/checklists/` 目录下，每份检查单一个 `.md` 文件 |
| 文件命名 | `<域标识>-Lens.md`，例如 `CCE-Lens.md`、`GeminiDB-Lens.md` |
| 一级标题 | `# <架构域> 架构评估检查单` |
| 头部声明 | 引用块标注检查单性质与「华为云对应」服务 |
| 支柱章节 | `## <支柱标识> — <支柱名称>（N 题）`，N 为该支柱实际题数 |
| 题目条目 | `### <题号> <题目标题>`，正文含「说明」「期望回答（参考）」 |

## 2. 新建检查单的步骤

1. **确定架构域与对应服务**：先明确要覆盖的服务域（如消息队列、缓存），并确定其华为云对应服务。
2. **复制相近的检查单作为骨架**：同支柱体系的检查单结构最接近，直接复制其文件再逐题替换内容，可保证三档自评与「期望回答」格式一致。
3. **定义支柱划分**：参考本仓既有体系（如安全 / 可靠性 / 性能效率 / 资源占用优化 / 运维卓越性 / 可持续性），按目标域裁剪，控制在 4～6 个支柱。
4. **编写题目**：每题聚焦一个可判定的架构决策，避免「是否良好」这类无法回答的问题；题目编号在同一支柱内保持连续。
5. **补充期望回答**：给出可参照的目标形态，让自评有客观依据而非主观印象。
6. **登记映射**：在检查单头部写明「**华为云对应**：<服务>（<域>）」，并在 `docs/lens-notes/` 下新增对应的领域说明文档。
7. **自检**：执行下方校验命令，确认题目数与支柱标注一致。

## 3. 校验命令

```bash
# 统计检查单数量
find src/checklists -name "*.md" | wc -l

# 统计某份检查单的题目数（每个 ### 为一题）
grep -c "^###" src/checklists/CCE-Lens.md

# 列出该检查单的支柱划分
grep "^## " src/checklists/CCE-Lens.md

# 校验各支柱标注的题数与实际条目数是否一致
grep -o "（[0-9]* 题）" src/checklists/CCE-Lens.md
```

## 4. 编写建议

- **题目要可判定**：把「是否建立了数据分类分级机制」这类可回答的问题，与「数据治理是否良好」这类不可回答的问题区分开。
- **期望回答要具体**：给出可落地的目标形态（如「桶策略显式拒绝未加密上传」），而不是「应当加强安全」这类无法执行的表述。
- **保持三档自评可用**：题目应能明确落到「良好 / 部分符合 / 不符合」中的一档。
- **服务名保持华为云语境**：检查单内涉及的服务一律使用华为云服务名，避免出现其他云厂商的服务专名。
